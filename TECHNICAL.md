# Technical Notes

## Employee category configuration

Employee branch, position, and employment status choices are stored in the `EmployeeCategory` table. The `type` values are `BRANCH`, `POSITION`, and `EMPLOYMENT_STATUS`; the migration seeds the existing employee-form options. Categories are soft-deactivated with `active = false`, preserving employee records that still contain an inactive value.

`/management/system-configuration` is available to administrators from the Management section in the sidebar. `/api/management/categories` allows administrators to list, add, and activate/deactivate categories. Authenticated users with employee-page access may read the categories for employee forms. New and updated employee profiles use active category values while preserving any currently selected legacy value.

## Employee directory views

The employee directory defaults to cards sorted A–Z by displayed first-middle-last name. The main toolbar and filters have no enclosing card wrapper or internal padding and sit directly on the page background, aligned within the page gutter rather than bleeding to the viewport edges. The icon-only Cards/List toggle, refresh-to-clear-filters, admin-only Transfer, Export, and Import controls are in the main toolbar, right-aligned and visible from the medium breakpoint; these controls are hidden on mobile. A left-aligned mobile magnifying-glass button toggles a vertically stacked search box and status, employer, and branch filters; its row keeps the Showing count beside it whether the filters are open or closed. A blue eye button immediately after the Branch filter opens the first alphabetically sorted employee in the current filtered result set, including active search/status/employer/branch filters; it is disabled when no employees match. On mobile it appears beside the Branch dropdown when filters are expanded. The collapsed mobile filter row and empty desktop quick-filter/count row do not reserve extra bottom spacing; the hidden transfer panel likewise has no collapsed bottom margin. Transfer appears before Export and Import. Activating it reveals employee selection checkboxes and an animated destination panel in normal document flow below the toolbar and filter row, so it cannot cover the employee cards. After at least one employee is selected, the destination branch and employer selectors and Transfer action are laid out horizontally when space allows and wrap on narrow screens; selectors use a consistent compact width instead of stretching to fill the panel. Branch and employer are independently optional; the admin-only `/api/employees/transfer` endpoint updates only supplied assignment fields. Successful transfers reload directory data and exit selection mode. The card shows bold Date Joined beside the photo; the list places the photo and name first, with the biometric number shown without a label below the name, followed by position, branch, employer, active status, phone, email, bold Date Joined, and actions. Joined dates use `MMM dd, yyyy`, and unset dates show “Not set.” Both card and list views have direct accessible eye (View) and pencil (Edit) icon buttons instead of a three-dot menu; in card selection mode, the transfer checkbox remains beside these actions. The filter and quick-filter toolbars are in normal document flow and scroll away with the page. On desktop, the sidebar collapse button stays at the original `top-20` sidebar/header boundary, protrudes above the title header, and remains clear of the collapsed sidebar logo. The status dropdown contains only Active employees and Inactive employees; quick filters may further select specific statuses. Search, status, employer, and branch filters apply to both views; there is no manual sort selector. Status, branch, and employer selections are synchronized to the directory query string and are the source of truth when returning from a profile; the profile link, Back link, and record-navigation links preserve the same values.

The employee profile page (`/employees/[id]`) uses an unboxed identity header with a slightly larger photo and employee details aligned in one row. The shared AppShell Back-to-directory button remains the only Back button; circular previous/next record controls are placed beside it in the shared header row and disabled at either end. Only Branch and Employer selectors are shown in the profile toolbar; both are initialized from the directory query parameters, and they align to the right of the shared header action row. Status is not exposed as a profile toolbar filter, but an inherited status query filter remains applied to navigation and is preserved in profile/back links. Selectors omit visible labels, expose accessible aria-labels, and use the directory filters' default text size. Changing either selector refetches the profile/navigation roster and opens the first alphabetically matching employee; if there are no matches, the current employee remains open at `00 of 00`. Navigation summaries otherwise come from the authorized employee-detail response. Profile responses are cached in memory for 30 seconds (up to 12 employee records), and adjacent records are prefetched so previous/next navigation can display cached employee details immediately. Prefetch requests omit the navigation summary, avoiding another full employee-list query; profile API responses are marked private/no-store, and the in-memory cache is cleared on logout. The Back and previous/next links retain the filters, and the shared header action slot gives focus rings room to render. Profile tabs and all profile cards have icons; card headings use normal sentence case. Personal Information contains the personal, contact, and emergency information cards. Government is named Government ID. The Employment tab has Contract Duration, Contract Position Details, and Contract Details cards. The Requirements tab contains 17 individually markable checklist items persisted per employee in `EmployeeRequirement`; updates use the authenticated `/api/employees/[id]/requirements` endpoint. The dashboard reports the number of employees with at least one unchecked requirement, visible only as an employee statistic when the user has employee-page access. Apply the employee job-level/supervisor and employee-requirements schema migrations to each database before running code that selects these fields: `npx prisma migrate deploy`. Service duration is rendered as zero-padded years/months/days with full unit words through today for active employees, or through End Date for ended employees; active contractual records also show calendar days remaining or elapsed past expiry. Job Level and Supervisor are persisted and editable in employee create/update forms. Job levels are Entry-level, Junior, Mid-level, Senior, Supervisor/Lead, Manager, and Executive. Supervisor assignment is restricted in both UI and API to another employee whose position is exactly Store In-charge. Expected weekly hours show `48 hours`.

Employee CSV export opens the browser's native Save As picker when available. Browsers without File System Access support use the standard download flow and may use the browser's configured download location. Successful employee exports and imports display a dismissible success popup.

Employee `assignedBy` audit values remain stored as account IDs for historical compatibility. Employee detail and directory APIs resolve numeric IDs in a batch (directory) or single lookup (profile), returning the user's display name, username, or email in that priority order. Legacy emails remain unchanged, `ADMIN` displays as Admin, and missing account references display as an explicit unknown-account label rather than an unexplained numeric ID.

## Contact directory

The Contacts page keeps its “Showing NN of NN contacts” count aligned in a row with an alphabet filter. Selecting A–Z filters by the first character of the current sort field (contact name or company name); `#` shows entries whose selected name starts with a non-ASCII-letter character or has no initial. “All” clears only the alphabet filter, while Clear filters resets search, category, and alphabet filters together.

## Dashboard birthday card

The dashboard birthday card shows upcoming birthdays as a horizontally scrollable row of three celebrant tiles with 80–84px photos (or initials), first name on the first line, last name on the second line, countdowns, and a month/day birthdate at the bottom. If an employee has multiple given names, only the first is shown in the tile. Celebrants whose birthday is today get an amber-highlighted card. No-tail left/right chevrons scroll the celebrant list in either direction, and the list is keyboard-focusable. The card has a 320px minimum height (360px at the small breakpoint and above) and tiles expand to use its vertical space. The footer shows the total upcoming count and a stacked avatar preview; “See all” links to the employee directory. The reminders API includes name parts, photo URLs, birthdate, and days-until values only for users allowed to view employees.
