# Project Memory

- Next.js app uses App Router pages under `app/` and route handlers under `app/api/`.
- API authentication uses `getAuthenticatedSession` from `lib/auth.ts`; employee data access is checked against `User.accessiblePages` for non-admin users.
- Employee branch, position, and status fields remain strings on the `employee` model. Their selectable values are managed in the `EmployeeCategory` table and are soft-deactivated to preserve existing employee data.
- The employee directory defaults to cards sorted A–Z by displayed first-middle-last name and supports a redesigned table list; toolbar and filters have no enclosing card wrapper or internal padding and stay aligned within the existing page gutter rather than bleeding to viewport edges. The icon-only view toggle, refresh-to-clear-filters, admin-only Transfer, Export, and Import are in the main toolbar, in that order, right-aligned and hidden on mobile (visible from the medium breakpoint). Mobile has a left-aligned magnifying-glass toggle and Showing count on the same row; the toggle reveals a vertically stacked search box and status, employer, and branch filters. A blue eye button after the Branch filter opens the first alphabetical current filtered result, including active search/status/employer/branch filters; it is disabled when no results match and appears beside Branch on mobile. Collapsed mobile filters and empty mobile-hidden toolbar rows do not retain excess bottom spacing; the collapsed transfer panel has no bottom margin. The transfer toggle matches the other toolbar controls' height and shadow; activating it reveals employee checkboxes and an animated destination panel in normal document flow below the toolbar and filter row, pushing cards down rather than covering them. Destination branch and employer selectors use a compact consistent width, are horizontal when space allows, and wrap on narrow screens; the action is labeled Transfer. Branch and employer are independently optional. The admin-only `/api/employees/transfer` supports branch-only, employer-only, or combined changes. Bold Date Joined uses `MMM dd, yyyy` beside the card photo and after Email in list view. Both card and list views use direct accessible eye (View) and pencil (Edit) icon buttons instead of the three-dot action menu; the card checkbox remains beside these icons in transfer selection mode.
- Employee CSV export prefers the browser Save As picker and falls back to the normal download mechanism when the picker API is unavailable.
- The Contacts directory shows an accessible A–Z and `#` alphabet filter beside its matching-count summary. Filtering applies to the first character of the selected sort field (contact or company name); `#` groups non-A–Z/empty initials, and Clear filters resets it with search and category.
- The admin contact PATCH route loads the existing contact once, derives its effective category/employee link for partial updates, and validates linked Employee Contacts against active employee statuses before saving.
- Employee `assignedBy` audit values remain stored unchanged; detail and directory API responses resolve numeric user IDs to the account name, username, or email, while preserving legacy email values and explicitly labeling Admin or missing accounts.
- Employee directory import/export success feedback is shown in a dismissible popup notification.
- The employee directory status dropdown offers only Active employees and Inactive employees; separate quick filters remain available for specific employee statuses.
- The employee profile `/employees/[id]` uses an unboxed header with a slightly larger photo and aligned employee details. The shared AppShell Back-to-directory button is the only Back button; circular previous/next record controls are provided in the same shared header row through `useAppHeaderActions` and disabled at either end. Record navigation follows the directory's alphabetized full-name order. Tabs and cards have icons and card headings use sentence case. Personal Information contains personal, contact, and emergency cards; Government is labeled Government ID. Employment contains Contract Duration (calendar service tenure with full years/months/days words and contractual expiry), Contract Position Details (job role, persisted level, 48 expected work hours per week, and supervisor), and Contract Details (employer, branch, start date). Job Level choices are Entry-level, Junior, Mid-level, Senior, Supervisor/Lead, Manager, and Executive. Job Level and Supervisor persist on Employee and are editable in create/update forms. Only another employee with exact position Store In-charge is eligible as Supervisor; the API enforces this constraint.
- Employee Directory Status, Branch, and Employer filters are reflected in query parameters and remain authoritative when returning from a profile. Profile toolbar exposes only Branch and Employer selectors, initializes them from and updates those parameters, and aligns them to the right of the shared header action row beside Back and previous/next controls (wrapping on narrow screens), not in a separate card. The shared action wrapper has no padding and the actions area expands to provide the right alignment. Status is hidden on profile but an inherited status query filter remains active for navigation and is preserved in profile/back links. Selectors are unlabeled visually, use the directory filter font size, and have accessible aria-labels. Changing either visible profile filter refreshes employee/navigation data and opens the first alphabetized match; if nothing matches it keeps the current profile open at `00 of 00`. The same query filters scope alphabetized previous/next navigation and the “Navigating … · Showing NN of NN” count. Back and navigation links preserve filter values. The employee detail API supplies authorized navigation summaries (status, branch, employer ID, and employer name) for client-side filtering.
- Employee profile details are cached in memory for 30 seconds with a 12-record cap; previous and next records are prefetched. Prefetch requests omit the navigation summary to avoid repeating the full employee roster query. Detail API responses are private/no-store, and profile cache data is cleared at logout.
- Employee profiles include a Requirements tab with 17 named checklist items. Each check is persisted in `EmployeeRequirement` via the authenticated employee-requirements PATCH route; an employee is complete only when every defined requirement key is marked complete. Dashboard employee statistics include employees missing at least one requirement.
- Employee filter controls and quick filters are in normal document flow and scroll away with the page. The desktop sidebar toggle sits at the original sidebar/header boundary (`top-20`), protruding from the sidebar edge without overlapping the collapsed sidebar logo.
- The dashboard birthday notification card uses a taller (320–360px minimum) horizontal carousel showing three celebrant tiles with large (80–84px) photos, first and last names on separate lines, countdowns, and month/day birthdates. Only the first given name is shown. Celebrants whose birthday is today get an amber highlight. No-tail left/right chevrons navigate the keyboard-focusable list.
- Consult the installed Next.js docs under `node_modules/next/dist/docs/` before adding or changing Next.js conventions.
